## What this job consumes (pinned)

- Fabric job F-018, merged at commit `cad7d1b` (PR #62): **dispatch-anchor contract v1.0.0**
  (fabric RFC 0054, CONTRACTS.md section 12). `GET /api/runs/{session_id}/chain` returns a
  top-level `chain_head`: the full 64-char `chain.sha256` of the final envelope, exactly as
  sealed; `null` on an empty chain and `null` when verification fails.
- rfsdk-kernel from the sibling repo `agentic-native-port`, **pinned to commit `9dcbd01`**
  (main after PR #1 relaxed `requires-python` to `>=3.12,<3.14`). Dev install is an editable
  path install from `../agentic-native-port/packages/kernel` (the fhirforge precedent in
  fabric). rfsdk provides `Dispatcher(evidence, policy, approvals, changes, clock)` whose
  `dispatch(name, args, caller, ...)` runs a registered action through a governed pipeline and
  seals exactly one hash-chained `SealedEnvelope` per outcome; the consumer supplies adapters
  for the port Protocols.

## Goal

Under `OPENWORKER_EXECUTOR=temporal`, every Temporal activity runs through
`Dispatcher.dispatch`, so the harness's own coordination steps leave a verifiable rfsdk
evidence chain, and the envelope for the step that completes a fabric run records fabric's
final `chain_head` (plus the fabric session id) as data. The rfsdk chain is the outer
authority; fabric's chain becomes a sub-chain referenced by hash. Fabric is untouched by rfsdk
(the anchoring is data, per the register's layering decision).

With the env unset, nothing changes: the sweep thread and SQLite journal path never import
rfsdk, exactly as phase 1 keeps `temporalio` out of `sys.modules`.

## Scope

1. `coworker/rfsdk_adapters/`: SQLite-backed adapters (WAL, one db under the state dir) for the
   four ports the Dispatcher requires:
   - `EvidenceStore`: append refuses a tampered seal (`invalid_envelope`) and a stale
     `prev_hash` (`chain_conflict`); `head`; `verify` recomputes every hash and link.
   - `ApprovalStore`: single-use consume, approver is never the requester, TTL expiry.
     Present because the Dispatcher requires the binding; harness actions set
     `needs_approval=False`, so the fabric part11 signoff stays the ONLY human gate.
   - `ChangeBus`: monotonic versions; `since` filtered by the caller's org; an unscoped change
     reaches nobody (fail closed).
   - `Policy`: tenant isolation. The caller's `org_id` is the work item's tenant; a call whose
     args name another tenant, or a caller without an org, is denied (escalation: tenancy).
2. rfsdk actions `ow.frame_work_item`, `ow.execute_work_item`, `ow.check_signoff`,
   `ow.sign_work_item`, `ow.emit_receipt`, `ow.learn_work_item` (`needs_approval=False`),
   each handler wrapping the existing activity body unchanged. The Temporal activities in
   `coworker/dispatch/temporal_executor.py` route through `Dispatcher.dispatch`; the caller is
   a service principal whose `org_id` is the item's tenant, so the policy check runs on every
   dispatch.
3. The anchor: when a stage observes the fabric run terminal (a non-gated execute, or the
   sign stage after signoff), it reads fabric `GET /chain`, requires `verified` true and a
   non-null `chain_head`, and returns `fabric_anchor: {session_id, chain_head}` in its result,
   which the Dispatcher seals into that action's envelope. Fail closed: `verified` false or a
   null head refuses the stage (`anchor_unavailable`), it never fabricates or omits silently.
4. The receipt body stays byte-identical to receipt-digest v1.0.0: anchor data lives in the
   rfsdk envelope only, never in the signed receipt body. Never retry a 4xx (unchanged).

## Acceptance (binary, from the register)

A1. After one governed run under `OPENWORKER_EXECUTOR=temporal`, rfsdk
    `EvidenceStore.verify(chain)` passes for the tenant's chain AND the run-completing action's
    envelope contains exactly the head returned by fabric's `GET /chain` for that session.
    Recorded in `factory/GATES.md` like the phase 1 proof.
A2. Each adapter passes its rfsdk port contract suite (`rfsdk_kernel.testing.contracts`):
    EvidenceStoreContract, ApprovalStoreContract, ChangeBusContract, PolicyContract.
A3. A null `chain_head` or `verified: false` from fabric refuses the anchoring stage; no rfsdk
    envelope claims an anchor it did not read.
A4. Tenant isolation: a caller org cannot read another org's changes; the policy denies a call
    naming another tenant.
A5. Env unset: the local gate passes at its `docs/known-failures.md` baseline and `rfsdk_kernel`
    stays out of `sys.modules` (same proof shape as `tests/test_temporal_optin.py`).
