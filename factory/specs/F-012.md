# F-012 — receipt forgery resistance, level 2 (rebuild)

Status: approved (vijay, 2026-11-06 — factory/GATES.md F-012 spec row; the freeze-at-signing
decision was accepted there and is not relitigated here). This spec is the rebuild of a job whose
verify gate was REVERSED on 2026-11-06: the joined run proved the digest never reached the
evidence store, so `signed_over_content` was local arithmetic, not a signature claim.

Contract: fabric **receipt-digest v1.0.0** — `regagentic-fabric/CONTRACTS.md` §11, RFC 0053,
fabric jobs F-013 (accept, validate, seal, terminal-only), F-014 (record before signoff) and
F-015 (chain exposure, duplicate/terminal refusals, restart durability). Merged to fabric `main`
2026-11-06 as commit `9fa5c92a4e552fbf45886921e331db6cc8799f1c` (PR zkumar/regagentic-fabric#58).
Fabric owns this contract; the harness consumes it and invents no fields.

## Goal

The emitted JSON receipt must be forgery resistant at level 2: the human Part 11 signature covers
the exact receipt bytes the consumer files. The harness computes
`sha256(canonical signed body)` and posts it to
`POST /api/runs/{run}/receipt-digest` BEFORE `POST /signoff`; fabric seals it into the final
decision envelope's `payload` as `receipt_digest`, so `chain.sha256` — and therefore the
signature — covers it. A forger who edits the receipt and recomputes `content_sha256` is still
caught, because the recomputed signed-body digest no longer matches the digest under the seal.

## The gap this rebuild closes (freeze at signing)

`SIGNED_BODY_EXCLUDES = ("signature", "sealed", "status")` was too narrow. The signature appends
the run's final sealed step, so `steps`, `evidence.chain_head`, `evidence.envelopes` and
`awaiting_signoff` all mutate AFTER the digest was computed. A digest recomputed over the emitted
receipt therefore never matched the digest computed at signing — even against a fabric that seals
it.

Per the accepted decision, the signed body is **frozen at signing**:

- At the moment the digest is computed (immediately before the digest post), the signing path
  snapshots the signed body and persists it on the work item (`SIGNED_BODY_KEY`). The freeze is
  saved before the digest leaves the harness, so emission after a restart stays byte-stable.
- Every receipt emitted after signing carries the frozen signed fields byte-for-byte; only the
  signature-derived fields are read live.
- `awaiting_signoff` joins `SIGNED_BODY_EXCLUDES`: like `signature`, `sealed` and `status`, it
  only restates whether the signature exists, and it flips BECAUSE the human signs, so it cannot
  sit inside what the signature covers. The content the human reviewed (`steps`, `evidence`,
  `decision`, …) is frozen, not excluded.
- The exclusion list stays recorded in `integrity.signed_body_excludes`, and verification uses
  the module constant, never the receipt's own list (a forger must not choose their own excludes).

## Acceptance

A1. One builder (kept from the first build): `coworker/receipts.py::receipt_body` is the single
    source for the bytes digested and the bytes emitted.
A2. Byte-stability: the digest posted pre-signoff equals `integrity.signed_body_sha256` of every
    receipt emitted after the signature appends the final step, with no recomputation drift.
A3. The freeze is persisted on the item before the digest post, and the emitted receipt's
    signature-derived fields (`signature`, `sealed`, `status`, `awaiting_signoff`) are live — a
    sealed receipt never claims it is still awaiting signoff.
A4. Best-effort against an older fabric: a failed digest post (endpoint missing, fabric down)
    never blocks the sign; the receipt stays level 1 (locally verifiable, not chain-sealed).
    Never retry a 4xx.
A5. `verify_receipt`: `signed_over_content` is true iff the digest recomputed over the emitted
    receipt (minus excludes, minus `integrity`) matches the claimed `signed_body_sha256`; a
    one-byte edit to any signed field flips it to false, even when the forger recomputes
    `content_sha256`.

## Verification

V1. Unit: byte-stability across the final step append, live derived fields, and the one-byte-edit
    flip (`tests/test_receipt_verification.py`, `tests/test_receipt_body.py`); the signing path
    freezes before it posts and posts before it signs (`tests/test_receipt_digest_call_site.py`).
V2. Local gate: the 8 test files in `docs/known-failures.md` (baseline 41 passed, 2026-11-06)
    plus `cd surfaces/gui && npm run build`.
V3. Joined run against merged fabric main (commit `9fa5c92a4e552fbf45886921e331db6cc8799f1c`),
    the binary criterion from the register entry
    (`features/receipt-digest-contract.md`): post the digest, sign, `GET /api/runs/{id}/chain`,
    then prove (a) the final sealed envelope's payload carries exactly the posted
    `receipt_digest`, (b) its chain hash and signature therefore cover it, (c) `verify_receipt`
    on the emitted receipt returns `signed_over_content: true`, (d) a one-byte edit to any signed
    field flips it to false. Recorded in `factory/GATES.md` as the F-012 re-verify row.
